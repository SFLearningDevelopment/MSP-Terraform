Providers

How Terraform finds, installs and versions providers, and how to use more than one provider or region in the same configuration.

Before you begin

In Module 1 you saw that providers are the plugins Terraform uses to talk to each platform. In this module you tell Terraform exactly which providers to use and which versions are allowed, and you learn what the lock file is for.

1

The terraform block and required_providers

Declare which providers a configuration needs.

Every configuration should say which providers it needs. You do this inside the terraform block, in a required_providers block.

versions.tf

terraform {
  required_version = ">= 1.12.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
  }
}
SettingWhat it means
aws (the key)The local name you use for this provider in your configuration.
sourceWhere the provider comes from, as namespace/type. hashicorp/aws means the Terraform Registry, namespace hashicorp, type aws. The full address is registry.terraform.io/hashicorp/aws.
versionWhich provider versions are allowed.
required_versionWhich versions of Terraform itself (the CLI) may run this configuration.

Where providers come from

Providers are published on the Terraform Registry. They come in three tiers: Official (owned by HashiCorp), Partner (owned by a technology company that works with HashiCorp) and Community (published by individuals or groups).

Exam tip

If you leave out source, Terraform assumes hashicorp/<name>. It still works for HashiCorp providers, but always writing source is the recommended practice.

2

Version constraints and the lock file

Control which versions install, and keep every run on the same versions.

Version constraint operators

ConstraintAllows
= 6.2.0 or 6.2.0Exactly 6.2.0
>= 6.06.0 or any newer version, including 7.x
~> 6.06.0 and newer, but below 7.0
~> 6.2.06.2.0 and newer, but below 6.3.0
>= 6.0, < 6.5Any version from 6.0 up to, but not including, 6.5
!= 6.3.1Any version except 6.3.1

The ~> operator is called the pessimistic constraint. It allows the right-most number you wrote to go up, and nothing to its left. ~> 6.0 allows minor updates; ~> 6.2.0 allows only patch updates.

The dependency lock file

When terraform init installs providers, it records the exact versions it chose, and their checksums, in .terraform.lock.hcl. Later runs of init use the recorded versions, even if newer versions matching your constraint have been released.

.terraform.lock.hcl (generated, do not edit)

provider "registry.terraform.io/hashicorp/aws" {
  version     = "6.2.0"
  constraints = "~> 6.0"
  hashes = [
    "h1:...",
  ]
}
  • Commit .terraform.lock.hcl to Git, so everyone on the team and every pipeline uses the same provider versions.
  • Do not commit the .terraform/ folder. It holds the downloaded provider binaries and is recreated by init.
  • To move to a newer allowed version, run terraform init -upgrade. This updates the lock file.
Watch out

The lock file records provider versions only. It does not record module versions and it does not record the Terraform CLI version.

3

How Terraform uses providers

Provider configuration, aliases and more than one provider.

A provider block configures a provider: for AWS, which region to use and which credentials to read.

providers.tf

provider "aws" {
  region  = "us-east-1"
  profile = "tf-lab"

  default_tags {
    tags = {
      Owner   = "tf-course"
      Project = "terraform-course-1"
    }
  }
}

default_tags adds the listed tags to every AWS resource that supports tags, so you do not repeat them on each resource.

More than one configuration of the same provider: alias

To work in two AWS regions from one configuration, add a second provider "aws" block with an alias. A resource then chooses it with the provider meta-argument. A block without an alias is the default.

provider "aws" {
  region = "us-east-1"            # default provider
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
}

resource "aws_s3_bucket" "east" {
  bucket = "demo-east-bucket-example"
}

resource "aws_s3_bucket" "west" {
  provider = aws.west             # use the aliased provider
  bucket   = "demo-west-bucket-example"
}

More than one provider

A configuration can use many providers at once. A common pairing is hashicorp/random, which creates random values such as name suffixes, alongside hashicorp/aws.

Behind the scenes, each provider is a separate program. Terraform starts it and talks to it over a local connection (RPC). This is what makes Terraform a plugin-based tool.

Exam tip

To find out which providers a configuration needs, and where each requirement comes from, run terraform providers.

4

Lab: pinned providers in two regions

Pin the AWS provider, generate unique names with random, and deploy to two regions.

Create a folder tf-lab-m2 with these three files.

tf-lab-m2/versions.tf

terraform {
  required_version = ">= 1.12.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.6"
    }
  }
}

tf-lab-m2/providers.tf

provider "aws" {
  region = "us-east-1"
  default_tags {
    tags = { Project = "tf-course-1", Lab = "m2" }
  }
}

provider "aws" {
  alias  = "west"
  region = "us-west-2"
  default_tags {
    tags = { Project = "tf-course-1", Lab = "m2" }
  }
}

tf-lab-m2/main.tf

# S3 bucket names must be unique across all of AWS.
resource "random_pet" "suffix" {
  length = 2
}

resource "aws_s3_bucket" "east" {
  bucket        = "tf-course-east-${random_pet.suffix.id}"
  force_destroy = true
}

resource "aws_s3_bucket" "west" {
  provider      = aws.west
  bucket        = "tf-course-west-${random_pet.suffix.id}"
  force_destroy = true
}

output "east_bucket" {
  value = aws_s3_bucket.east.bucket
}

output "west_bucket" {
  value = aws_s3_bucket.west.bucket
}
cd tf-lab-m2
terraform init          # installs aws and random, writes .terraform.lock.hcl
terraform providers     # shows both providers and their constraints
terraform apply         # type yes
cat .terraform.lock.hcl # see the exact versions chosen
terraform destroy       # type yes, removes both buckets
Check your work
  • terraform init lists hashicorp/aws v6.x and hashicorp/random v3.x
  • The AWS console shows one bucket in N. Virginia and one in Oregon
  • terraform destroy reports 3 destroyed (two buckets and the random name)
Try this

Change the AWS constraint to ~> 5.0 and run terraform init. Terraform refuses, because the lock file already records a 6.x version. Run terraform init -upgrade to let it choose again. Change it back to ~> 6.0 afterwards.
