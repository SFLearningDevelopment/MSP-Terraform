Resources and Data Sources

The difference between resource and data blocks, how to refer to attributes, and how references set the order Terraform works in.

Before you begin

Almost everything you write in Terraform is either a resource (something Terraform creates and looks after) or a data source (something Terraform only reads). In this module you use both, and connect them together into a small network with a web server.

1

resource and data blocks

Create and manage, or only read.

# resource: Terraform creates, updates and deletes this
resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}

# data: Terraform only reads this; it already exists
data "aws_availability_zones" "available" {
  state = "available"
}
resourcedata
PurposeCreate and manage an objectRead information about an existing object
Changes infrastructureYesNo
Addressaws_vpc.maindata.aws_availability_zones.available
Destroyed by terraform destroyYesNo, nothing to destroy
Typical useVPCs, buckets, instancesLatest AMI id, current account id, zones in a region, an existing VPC made by another team

Both block types have two labels: the type (for example aws_vpc, which also tells Terraform which provider to use) and the name you choose (for example main). The name must be unique for that type within the module.

Exam tip

A data source is read during plan when its arguments are already known. If an argument depends on a resource that does not exist yet, Terraform reads the data source during apply instead.

2

Referring to attributes

Use one object's values in another.

Every resource and data source exposes attributes: its own arguments plus values the platform returns, such as an id or an arn. You refer to them with a dot path:

ExpressionReturns
aws_vpc.main.idThe VPC id, known only after the VPC is created
aws_vpc.main.cidr_block"10.0.0.0/16"
data.aws_availability_zones.available.namesA list such as ["us-east-1a", "us-east-1b", ...]
data.aws_availability_zones.available.names[0]The first item: "us-east-1a"

In a plan, a value AWS has not created yet shows as (known after apply).

Addresses

The full resource address is how the CLI and the state refer to an object: aws_instance.web, data.aws_ami.al2023, or with an index when there are several: aws_subnet.public[0] or aws_subnet.public["a"]. Inside a module it gets a prefix: module.network.aws_vpc.main.

3

Dependencies

How Terraform decides the order to create things.

When one block refers to another, Terraform knows the second must exist first. This is an implicit dependency. Terraform builds a dependency graph from all the references and creates independent resources in parallel (up to 10 at a time by default).

resource "aws_vpc" "main" {
  cidr_block = "10.0.0.0/16"
}

resource "aws_subnet" "public" {
  vpc_id     = aws_vpc.main.id      # reference = implicit dependency on the VPC
  cidr_block = "10.0.1.0/24"
}

On destroy, the order is reversed: the subnet is destroyed before the VPC.

Occasionally two resources depend on each other in a way Terraform cannot see from references, for example an application that needs an IAM policy attached before it starts. For those cases there is depends_on, an explicit dependency. You will study it in Course 2. Prefer references whenever you can.

terraform graph | dot -Tsvg > graph.svg    # optional: draw the dependency graph (needs Graphviz)
Exam tip

References create implicit dependencies automatically. You do not need depends_on when one resource already refers to another.

4

Lab: a VPC with a web server

Look up an AMI and availability zones, and build connected network resources.

Create a folder tf-lab-m4. You will reuse this configuration in Modules 5 and 6.

tf-lab-m4/versions.tf

terraform {
  required_version = ">= 1.12.0"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 6.0" }
  }
}

provider "aws" {
  region = "us-east-1"
  default_tags { tags = { Project = "tf-course-1", Lab = "m4" } }
}

tf-lab-m4/main.tf

# ---------- Data sources (read only) ----------
data "aws_availability_zones" "available" {
  state = "available"
}

data "aws_ami" "al2023" {
  most_recent = true
  owners      = ["amazon"]
  filter {
    name   = "name"
    values = ["al2023-ami-2023.*-x86_64"]
  }
}

# ---------- Network ----------
resource "aws_vpc" "main" {
  cidr_block           = "10.0.0.0/16"
  enable_dns_hostnames = true
  tags                 = { Name = "tf-course-vpc" }
}

resource "aws_internet_gateway" "igw" {
  vpc_id = aws_vpc.main.id
  tags   = { Name = "tf-course-igw" }
}

resource "aws_subnet" "public" {
  vpc_id                  = aws_vpc.main.id
  cidr_block              = "10.0.1.0/24"
  availability_zone       = data.aws_availability_zones.available.names[0]
  map_public_ip_on_launch = true
  tags                    = { Name = "tf-course-public-a" }
}

resource "aws_route_table" "public" {
  vpc_id = aws_vpc.main.id
  route {
    cidr_block = "0.0.0.0/0"
    gateway_id = aws_internet_gateway.igw.id
  }
  tags = { Name = "tf-course-public-rt" }
}

resource "aws_route_table_association" "public" {
  subnet_id      = aws_subnet.public.id
  route_table_id = aws_route_table.public.id
}

# ---------- Security group: allow HTTP in, anything out ----------
resource "aws_security_group" "web" {
  name   = "tf-course-web"
  vpc_id = aws_vpc.main.id

  ingress {
    description = "HTTP"
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# ---------- Web server ----------
resource "aws_instance" "web" {
  ami                    = data.aws_ami.al2023.id
  instance_type          = "t3.micro"
  subnet_id              = aws_subnet.public.id
  vpc_security_group_ids = [aws_security_group.web.id]

  user_data = <<-EOF
    #!/bin/bash
    dnf install -y httpd
    echo "Hello from Terraform Course 1" > /var/www/html/index.html
    systemctl enable --now httpd
  EOF

  tags = { Name = "tf-course-web" }
}

output "ami_used" {
  value = data.aws_ami.al2023.id
}

output "web_url" {
  value = "http://${aws_instance.web.public_ip}"
}
cd tf-lab-m4
terraform init
terraform validate
terraform plan        # note which values show (known after apply)
terraform apply       # expect 7 to add

Wait about two minutes for the instance to start, then open the web_url output in a browser. You should see the hello message.

Look at the apply output: the VPC was created first, then the gateway, subnet and security group together, and the instance last. That order came from the references alone.

terraform destroy     # type yes; expect 7 destroyed
Check your work
  • The plan listed the data sources as data.aws_ami.al2023: Reading... and did not count them in 7 to add
  • The web page loaded from the web_url output
  • Destroy removed 7 resources
Watch out

Keep this folder. In Module 5 you will copy it and replace the fixed values with variables.

Module recap. resource blocks create and manage objects; data blocks read existing ones. Refer to attributes with type.name.attribute, or data.type.name.attribute. References create implicit dependencies and set the order of work.
