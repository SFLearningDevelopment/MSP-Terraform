Before you begin

So far each resource block created exactly one object. Real configurations need three subnets, or a security rule for each port in a list, or a larger server only in production. This module covers the tools for that: count, for_each, conditional expressions, for expressions, dynamic blocks and built-in functions.

The terraform console command lets you try expressions without creating anything. Use it throughout this module.

1

count and for_each

Create several similar resources from one block.

count

count takes a whole number and creates that many copies. Inside the block, count.index is 0, 1, 2 and so on.

resource "aws_subnet" "public" {
  count      = 2
  vpc_id     = aws_vpc.main.id
  cidr_block = "10.0.${count.index + 1}.0/24"     # 10.0.1.0/24, 10.0.2.0/24
}

# Addresses: aws_subnet.public[0], aws_subnet.public[1]
# All ids:   aws_subnet.public[*].id

for_each

for_each takes a map or a set of strings and creates one copy per item. Inside the block, each.key and each.value give the current item.

variable "subnets" {
  type = map(string)
  default = {
    a = "10.0.1.0/24"
    b = "10.0.2.0/24"
  }
}

resource "aws_subnet" "public" {
  for_each   = var.subnets
  vpc_id     = aws_vpc.main.id
  cidr_block = each.value
  tags       = { Name = "public-${each.key}" }
}

# Addresses: aws_subnet.public["a"], aws_subnet.public["b"]

Which one to use

With count, items are tracked by position. If you remove the first item of a list, every item after it moves up one place, and Terraform plans to change or replace them. With for_each, items are tracked by key, so removing "a" only affects "a".

  • Use count for a number of identical copies, or to turn a resource on or off: count = var.create_bucket ? 1 : 0.
  • Use for_each when each copy is different or has a meaningful name.
Watch out

A block cannot use both count and for_each. for_each does not accept a list directly; convert it with toset() first.

2

Conditions, for expressions and splat

Choose between values and reshape lists and maps.

Conditional expression

instance_type = var.environment == "prod" ? "t3.small" : "t3.micro"
#               condition                ? if true    : if false

for expressions

A for expression builds a new list or map from an existing one. Square brackets produce a list; curly braces produce a map.

locals {
  names = ["web", "api", "worker"]

  upper_names = [for n in local.names : upper(n)]
  # ["WEB", "API", "WORKER"]

  name_lengths = { for n in local.names : n => length(n) }
  # { api = 3, web = 3, worker = 6 }

  long_names = [for n in local.names : n if length(n) > 3]
  # ["worker"]

  subnet_ids = [for s in aws_subnet.public : s.id]   # works for count and for_each
}

Splat expressions

A splat is a short form of a simple for expression over a list. aws_subnet.public[*].id means the same as [for s in aws_subnet.public : s.id] when public used count. For resources that used for_each (a map), use the for form or values(aws_subnet.public)[*].id.

String templates

Inside double quotes, ${ ... } inserts a value: "web-${var.environment}". A heredoc (<<-EOF ... EOF) holds a block of text across many lines, such as a start-up script.

3

dynamic blocks and functions

Repeat nested blocks, and use the functions you will meet most often.

dynamic blocks

Some resources have nested blocks, such as ingress in a security group. A dynamic block creates one nested block for each item in a collection.

variable "open_ports" {
  type    = list(number)
  default = [80, 443]
}

resource "aws_security_group" "web" {
  name   = "web"
  vpc_id = aws_vpc.main.id

  dynamic "ingress" {
    for_each = var.open_ports
    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}

Inside content, the iterator is named after the block (ingress.value, ingress.key). Use dynamic blocks sparingly; too many make a configuration hard to read.

> cidrsubnet("10.0.0.0/16", 8, 1)

> [for i in range(3) : cidrsubnet("10.0.0.0/16", 8, i + 1)]

Exam tip

cidrsubnet(prefix, newbits, netnum): newbits is how many bits to add to the prefix length (/16 plus 8 gives /24), and netnum picks which of the new subnets.

4

Lab: subnets and ports from data

Rebuild the network with for_each, cidrsubnet, a dynamic block and a condition.

Copy your tf-lab-m5 folder to tf-lab-m6. You will change the subnet, route table association, security group and instance, and add variables.

Add to tf-lab-m6/variables.tf

variable "public_subnet_count" {
  type        = number
  description = "How many public subnets to create (1 to 3)"
  default     = 2
}

variable "open_ports" {
  type    = list(number)
  default = [80, 443]
}

Replace these blocks in tf-lab-m6/main.tf

locals {
  name_prefix = "tf-course-${var.environment}"
  common_tags = merge(
    { Project = "tf-course-1", Lab = "m6", Environment = var.environment },
    var.extra_tags
  )

  # One entry per subnet, keyed by availability zone name
  public_subnets = {
    for i, az in slice(data.aws_availability_zones.available.names, 0, var.public_subnet_count) :
    az => cidrsubnet(var.network.vpc_cidr, 8, i + 1)
  }
}

resource "aws_subnet" "public" {
  for_each                = local.public_subnets
  vpc_id                  = aws_vpc.main.id
  availability_zone       = each.key
  cidr_block              = each.value
  map_public_ip_on_launch = true
  tags                    = { Name = "${local.name_prefix}-public-${each.key}" }
}

resource "aws_route_table_association" "public" {
  for_each       = aws_subnet.public
  subnet_id      = each.value.id
  route_table_id = aws_route_table.public.id
}

resource "aws_security_group" "web" {
  name   = "${local.name_prefix}-web"
  vpc_id = aws_vpc.main.id

  dynamic "ingress" {
    for_each = var.open_ports
    content {
      description = "Port ${ingress.value}"
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "web" {
  ami                    = data.aws_ami.al2023.id
  instance_type          = var.environment == "prod" ? "t3.small" : "t3.micro"
  subnet_id              = values(aws_subnet.public)[0].id
  vpc_security_group_ids = [aws_security_group.web.id]
  user_data              = <<-EOF
    #!/bin/bash
    dnf install -y httpd
    echo "Hello from ${local.name_prefix}" > /var/www/html/index.html
    systemctl enable --now httpd
  EOF
  tags = { Name = "${local.name_prefix}-web" }
}

Remove the subnet_cidr attribute from the network variable type and default (it is now worked out with cidrsubnet), and remove the old instance_types variable. Then add these outputs:

Add to tf-lab-m6/outputs.tf

output "subnet_cidrs" {
  value = { for az, s in aws_subnet.public : az => s.cidr_block }
}

output "open_ports" {
  value = [for r in aws_security_group.web.ingress : r.from_port]
}
cd tf-lab-m6
terraform init
terraform console          # try: local.public_subnets   then exit
terraform plan             # 2 subnets, 2 associations, 2 ingress rules
terraform apply
terraform output subnet_cidrs

Now set public_subnet_count = 3 in terraform.tfvars and run terraform plan. Only one new subnet and one new association are added; the existing two are untouched, because for_each tracks them by zone name. Apply it, then clean up.

terraform apply
terraform destroy
Check your work

  • Raising the count to 3 planned 2 to add, 0 to change, 0 to destroy
  • The security group has one inbound rule each for 80 and 443

Module recap. count makes numbered copies; for_each makes keyed copies and handles removals safely. Conditions choose values, for expressions reshape collections, dynamic blocks repeat nested blocks, and built-in functions such as merge, lookup and cidrsubnet do the rest.
